# Base Station Storage

Серверный реестр хранилищ базы для Project Zomboid Build 42: ящики, холодильники, шкафчики и стеллажи, которые владелец убежища помечает один раз, после чего игра сама берёт из них ингредиенты и складывает туда вещи.

Заменяет мод Craft From Containers на нашем сервере: без зон крафта, без кнопки в панели убежища и без ожидания, пока игра досчитает зону.

## Что делает

- **Крафт из базы.** Зарегистрированные контейнеры подмешиваются в тот же список источников, которым пользуются ванильный крафт и Neat_Crafting. Отдельного окна крафта мод не создаёт.
- **Готовка из холодильника.** Ингредиенты берутся из тех же зарегистрированных контейнеров, включая холодильник и морозильник; готовка идёт через штатный интерфейс игры.
- **Автосортировка.** «Разложить по базе» отправляет вещи из контейнера или из инвентаря в зарегистрированные хранилища: сначала туда, где такой предмет уже лежит, затем в первое со свободным местом.
- **Только внутри убежища.** Хранилищами базы можно пользоваться, пока стоишь в своём убежище: отошёл за его границу — крафт и готовка перестают их видеть, а если клиент всё же пришлёт такой запрос, сервер откажет и напишет причину.
- **Роли у каждого контейнера.** «Давать ингредиенты» и «принимать при раскладке» переключаются отдельно: холодильник может кормить готовку, но не забиваться гвоздями.
- Реестр живёт на сервере, сохраняется в сейве мира и синхронизируется клиентам, поэтому переживает рестарт и един для всех игроков.

## Установка на сервер

```sh
scripts/check.sh              # синтаксис Lua 5.1, JSON переводов, юнит-тесты
scripts/deploy.sh --dry-run   # собрать пакет и проверить транспорт, сервер не трогать
scripts/deploy.sh --restart   # установить и перезапустить контейнер
scripts/verify.sh             # проверка уже развёрнутой копии (только чтение)
```


Требуется включённый сейфхаус на сервере: `PlayerSafehouse=true` или `AdminSafehouse=true` в `servertest.ini`. Без сейфхауса мод откажет в регистрации — иначе «базой» мог бы объявить что угодно любой игрок.

## Как пользоваться в игре

1. Захватите убежище (ПКМ по полу в здании → «Захватить убежище»).
2. ПКМ по ящику, холодильнику или шкафчику → **База** → **Добавить в базу**.
3. Там же переключаются роли и снимается регистрация; «Показать список базы» печатает реестр в консоль клиента.
4. Крафт и готовка сразу видят содержимое этих контейнеров — как если бы они были открыты рядом.
5. «Разложить по базе» на контейнере-источнике или «Разложить инвентарь по базе» в меню инвентаря разносит вещи по хранилищам.

Регистрация доступна владельцу убежища и его жителям, а также админам и модераторам. Проверка идёт **по квадрату контейнера**, а не по позиции игрока: стоя в соседней комнате, чужой холодильник не зарегистрируешь.

## Модель доверия

Клиент только просит, решает сервер:

- `server/BSSServer.lua` принимает команды `add`/`remove`/`toggle`/`sync`, проверяет координаты, существование контейнера, сейфхаус и права, и лишь потом пишет в глобальный `ModData` и рассылает его игрокам.
- `server/BSSGuard.lua` применяет правило мода к списку контейнеров, который пришёл от клиента: ванильный `ISHandcraftAction:serverStart()` пересобирает логику крафта именно из него, а `manualInputs` java вообще не проверяет — предмет ищется по ID в любом контейнере мира. Контейнер допустим, если он рядом (≤3 клетки, ванильная досягаемость) либо зарегистрирован и игрок стоит в том же убежище, что и контейнер. Всё прочее отклоняется с сообщением игроку и записью в лог, а недопустимые предметы вычищаются из ручных входов. Контейнеры без мирового квадрата (сумки, машины, трупы) не проверяются — иначе сломается ванильное поведение.
- Там же второй, менее очевидный механизм: java-проверка `BaseCraftingLogic.isContainersAccessible()` отказывает контейнеру дальше 2.5 тайла от игрока, и переопределить её из Lua нельзя. Поэтому для зарегистрированных доноров `performRecipe` выполняется нашим кодом: `updateFloorContainer` → `recipeData:perform(...)` → выдача результата через `Actions.addOrDropItem` → `luaCallOnCreate` → `processDestroyAndUsedItems`, то есть ровно хвост ванили без проверки дистанции. Ошибка в этом пути только логируется: повторного ванильного прохода нет, чтобы не списать предметы дважды.

Радиус 3 клетки — не украшение: это предел, на котором игра вообще показывает содержимое контейнера, поэтому обёртка может только добавлять источники, но никогда не отнимает доступное.

## Ограничения

- Мод должен стоять **и на клиенте, и на сервере**. Это локальный мод, а не предмет Мастерской: сервер не раздаёт его автоматически, файлы игрокам нужно передать (архив) — иначе клиент не увидит ни меню, ни общих контейнеров.
- Только мультиплеер: в одиночной игре серверной стороны нет, мод не активируется.
- Контейнеры в незагруженных чанках не дают ингредиентов: клиент не знает их содержимое. База должна быть в загруженной части карты.
- **Нагрев еды остаётся ванильным.** Собрать блюдо (салат, суп, бургер) из зарегистрированного холодильника можно, а пожарить сырое мясо «через комнату» — нет: нагрев живёт в Java и требует, чтобы еда физически лежала в контейнере плиты, а плита была включена.
- Автосортировка выполняется штатным `ISInventoryPane:transferItemsByWeight`: на каждый предмет ставится одно обычное действие переноса, как у кнопки «Перенести всё».
- Идентификатор контейнера — квадрат плюс тип контейнера. Если игрок снесёт объект и построит другой того же типа на том же месте, он унаследует регистрацию.
- Стройка (`ISBuildIsoEntity`) тоже пересобирает логику из клиентского списка контейнеров, но расход там идёт через `BaseCraftingLogic.isContainersAccessible`, поэтому java сама не даст строить дальше 2.5 тайла. Зарегистрированные контейнеры в строительстве не помогают — это ограничение, а не дыра.
- Администраторы и модераторы правило «только внутри убежища» не проходят: им хранилища доступны откуда угодно, как и остальные админ-возможности.
- Легаси-крафт (`ISCraftAction` → `RecipeManager.PerformMakeItem`) серверной проверки дистанции не имеет вовсе — это ванильная особенность; наш guard её пока не покрывает.
- Пакет таймед-экшена java проверяет только «id != -1» (`IDShort.isConsistent`), то есть подделанный пакет может заявить чужого персонажа. Из Lua это не закрывается — известное ограничение движка, а не мода.

## Что проверить в игре после установки

Каждый пункт — то, что нельзя проверить офлайн-гейтом:

1. ПКМ по ящику внутри своего убежища → «База» → «Добавить в базу». Ожидаемо: «Контейнер добавлен в базу (1)», в логе сервера `[BaseStationStorage] server ready, registered containers: 1`.
2. Перезапустить сервер, зайти снова: контейнер по-прежнему в базе (реестр лежит в `global_mod_data.bin` сейва).
3. Взять в руки рецепт, все ингредиенты которого лежат **только** в зарегистрированном ящике в другом конце базы (дальше 2.5 тайла), стоя при этом внутри убежища → крафт должен пойти и списать предметы из ящика.
4. Выйти за границу убежища и повторить тот же рецепт → крафта нет, в чате/подсказке «База: хранилища доступны только внутри убежища».
5. Собрать блюдо (салат/суп) из продуктов, лежащих только в зарегистрированном холодильнике.
6. «Разложить инвентарь по базе»: вещи уходят в контейнеры с ролью приёма, одинаковые — в те ящики, где такие уже лежат.
7. Не-админ вне своего убежища пробует зарегистрировать чужой ящик → «База: менять может только владелец убежища или админ».
8. Подделанный клиент со списком чужого дальнего ящика → в логе сервера `[BaseStationStorage] craft rejected for <ник>: container outside base ...`, крафта нет.

## Структура

```
common/mod.info                                     манифест мода
common/media/lua/shared/BaseStationStorage/BSS.lua         константы и чистые функции (ключи, права, выбор цели)
common/media/lua/shared/BaseStationStorage/BSSData.lua     реестр в ModData и привязка к объектам мира
common/media/lua/shared/Translate/{RU,EN}/UI.json          тексты меню и сообщений
common/media/lua/server/BaseStationStorage/BSSServer.lua   авторитетная сторона: команды, проверки, запись
common/media/lua/server/BaseStationStorage/BSSGuard.lua    проверка списка контейнеров при крафте
common/media/lua/client/BaseStationStorage/BSSClient.lua   меню, запросы, ответы сервера
common/media/lua/client/BaseStationStorage/BSSContainers.lua  подмешивание в крафт-UI (одна точка)
common/media/lua/client/BaseStationStorage/BSSSort.lua     автосортировка
tests/logic_test.lua                                юнит-тесты чистой логики
scripts/{check,deploy,verify}.sh                    гейт, деплой, проверка
```

`common/` — не прихоть: B42 регистрирует мод только при наличии каталога версии (`common` или `42.x`), причём вместе с `mod.info` и `media` внутри него. Мод без такого каталога сервер молча не находит и пишет в лог `required mod "<id>" not found`, хотя файлы лежат на месте.

Каталоги, которые сервер вообще просматривает (`ZomboidFileSystem.getAllModFolders`): предметы Мастерской (staged и installed) и **`<cachedir>/mods`, то есть `Zomboid/mods`**. Каталог `mods` внутри установки игры выделенный сервер не сканирует — моду там делать нечего.

## Разработка

```sh
apk add lua5.1      # luac5.1 — диалект, на котором работает Kahlua в игре
scripts/check.sh
```

`check.sh` — обязательный гейт: `luac5.1 -p` по всем файлам, разбор JSON переводов, проверка `mod.info` (id совпадает с каталогом и нет `require=`) и юнит-тесты. Ошибка синтаксиса в моде не видна в логе сервера — мод просто молча выкидывается из списка, поэтому гейт важнее логов.
