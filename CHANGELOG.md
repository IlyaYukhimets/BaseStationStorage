# CHANGELOG

## 1.1.1

### Исправлено

- Администраторы и модераторы больше не обходят правило «только внутри убежища» при использовании хранилищ: допуск теперь зависит от места, а не от ранга. Право управлять реестром (регистрировать и снимать контейнеры в любом убежище) за админами оставлено осознанно — это администрирование, а не доступ к запасам.

## 1.1.0

Правило доступа изменено по требованию владельца: хранилищами базы можно пользоваться только изнутри своего убежища.

### Изменено

- Правило допуска (`BSS.canUseRole`): контейнер разрешён, если он рядом (≤3 клетки, ванильная досягаемость) либо зарегистрирован с нужной ролью, и игрок в этот момент стоит в том же убежище, что и контейнер. Раньше зарегистрированные доноры работали с любого расстояния — это была ошибка проектирования.
- Тот же фильтр применяется к серверному guard'у крафта, к списку контейнеров в крафт-UI и подсказках (клиент не предлагает невозможный рецепт) и к целям автосортировки.
- Отказ сервера теперь виден игроку: `sendServerCommand(..., "denied", {err})` и текст «База: хранилища доступны только внутри убежища» / «…этот контейнер не из базы и слишком далеко».
- Сравнение убежищ идёт по границам (`BSS.sameRectangle`), а не по идентичности объектов: игра не гарантирует один и тот же экземпляр `SafeHouse`.

### Ограничения, зафиксированные в README

- Администраторы и модераторы правило не проходят — им база доступна откуда угодно.
- Легаси-крафт (`ISCraftAction` → `RecipeManager.PerformMakeItem`) серверной проверки дистанции не имеет вовсе; guard этот путь не покрывает.

## 1.0.0

Мод переписан с нуля. Версия 0.1.0 была концептом и не загружалась на сервере.

### Исправлено

- `mod.info`: убрано самотребование `require=\BaseStationStorage`, из-за которого сервер писал `required mod "BaseStationStorage" not found` и молча выбрасывал мод из списка.
- `BaseStationStorageShared.lua:39`: `safehouse:playerAllowed` без вызова — синтаксическая ошибка, файл не компилировался.
- `BaseStationStorageClient.lua:10`: `actual[1]:getContainer` без вызова — то же самое.
- Проверка прав переведена на квадрат контейнера (`SafeHouse.isSafeHouse` + `playerAllowed`/`getOwner`), а не на позицию игрока; убран fail-open `if not SafeHouse then return true end`.
- Контейнер определяется по `getSourceGrid()`: у сумок и контейнеров внутри контейнеров мирового квадрата нет, и регистрировать их нельзя.

### Добавлено

- Серверная авторитетная сторона: команды `add`/`remove`/`toggle`/`sync`, проверка координат, существования контейнера, сейфхауса и прав, запись в глобальный `ModData` с рассылкой клиентам. Реестр переживает рестарт сервера.
- Подмешивание зарегистрированных контейнеров в `ISInventoryPaneContextMenu.getContainers` — одна точка, покрывающая крафт, готовку и стройку, без собственного окна крафта.
- Обёртка `CraftTooltip:getContainers`: без неё подсказки рецептов недосчитывали предметы из базы.
- Серверная проверка списка контейнеров в `ISHandcraftAction:serverStart` плюс вычистка недопустимых предметов из `manualInputs` (java их не проверяет вообще).
- Обход java-проверки дистанции 2.5 тайла для зарегистрированных доноров: собственный `performRecipe` (`updateFloorContainer` → `recipeData:perform` → `Actions.addOrDropItem` → `luaCallOnCreate` → `processDestroyAndUsedItems`). Без этого крафт из ящика в другом конце базы молча не находил ингредиентов.
- Автосортировка: раскладка из контейнера и из инвентаря по зарегистрированным хранилищам, с учётом вместимости и с приоритетом «туда, где такой предмет уже лежит».
- Роли контейнера: выдача ингредиентов и приём при раскладке переключаются независимо.
- Переводы RU/EN вместо сырых ключей в меню.
- Тесты чистой логики (`tests/logic_test.lua`, 36 проверок) и обязательный гейт `scripts/check.sh` (Lua 5.1, JSON, `mod.info`, тесты).
- Скрипты `deploy.sh` (tar-поток, staging, владелец 1000:10, атомарная замена, рестарт по флагу) и `verify.sh` (только чтение: файлы, права, регистрация в ini и `default.txt`, синтаксис развёрнутой копии, строки лога).
